# 写作联网检索

`useWebResearch` 入参与草稿 `research` 字符串不变。任务中心管理进度与取消，首稿共享资料，续改复用父稿资料。

## 当前链路

用户要求＋已有素材＋支持文档 → 一次 Responses `web_search` → 带来源的简短文本 → 写作模型。

搜索补充背景、具体信息、实例和观点，不逐项审查已有素材。信息够用即结束，查不到的细节略过；明显矛盾简短指出，不输出核实清单、免责声明或写作建议。完整提示词见 `src/lib/writer-prompts.ts` 的 `writerWebResearchInstruction()`。

没有独立规划、逐对象队列、反思循环、二次摘要或事实／缺口 JSON 分类。模型直接返回自然文本，不强制表格、条数或事实来源 schema。来源由模型随条附上，程序不声称已自动核验真实性。

## 执行与兼容

- 写作联网总预算 60 秒，含缓存等待和所有尝试，不含转写、文档读取和正文生成。
- 沿用用户模型与推理设置，输出预算 5000 token（含推理）。当前中转节点拒绝 `max_tool_calls`，不发送它。
- 最多两次 HTTP 请求，后一次须剩余至少 20 秒；瞬时故障可非流式重试。所有尝试共享截止时间。
- 必须实际调用搜索工具、完整结束且输出非空。超时、断流、取消、无工具或外部错误明确失败，不生成模板或交付半截响应。其他业务的严格搜索入口保留原预算。
- 成功结果缓存 30 分钟，保留 schemaVersion、锁、并发合并、原子写入和损坏报错。版本 8 缓存指纹隔离旧结果，不删除旧缓存。
- 旧草稿中的 `【检索记录，仅供查阅】…【检索记录结束】` 块继续在传给写作模型时移除；新结果直接传递，不对用户素材或成稿删词。

## 设计参考与验证

参考 [Vane speed 研究器](https://github.com/ItzCrazyKns/Vane/blob/master/src/lib/agents/search/researcher/index.ts) 的有限检索与资料分离，独立实现，未复制代码或引入依赖。[LangChain Local Deep Researcher](https://github.com/langchain-ai/local-deep-researcher) 的多轮反思不适用于本次快速补充资料目标。接口参考 [OpenAI Web search](https://developers.openai.com/api/docs/guides/tools-web-search)，中转参数支持以实测为准。

回归覆盖多对象单次请求、自然文本直接传递、并发合并、缓存损坏、59 秒成功／60 秒超时、断流、取消、无搜索工具、空结果、首稿和续改复用，以及历史资料兼容。真实模型评测使用隔离资料库，单独记录联网耗时和正文耗时。
