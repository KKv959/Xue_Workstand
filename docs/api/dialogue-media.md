# 对话中下载与转写视频

用于在本机任意 Codex 项目或对话中，直接复用工作台已有的单条视频接口。无需安装新技能，也无需打开工作台页面。工作台服务必须运行；默认地址为 `http://127.0.0.1:3000`。

## 范围与存储

- 支持抖音、B站单条视频链接；可从分享文案中提取链接。多个链接逐条处理，只执行用户要求的下载、音频提取或转写。
- 不支持通过这两个接口上传本地音视频，也不承诺支持其他平台。遇到这些输入先说明范围，再按用户需求选择已有的适用工具。
- 直接调用下述接口，不创建账号，不采集账号列表，不创建素材或草稿，不调用 `/api/jobs`。这两个同步接口不创建任务中心记录，也不提供任务 ID、断点恢复或进度轮询。
- 媒体处理中仍会产生临时文件、运行日志，并使用现有浏览器登录状态；“不入库”不代表没有临时文件或第三方处理。转写沿用服务端配置，可能调用火山识别及已启用的文本清洗模型。
- 文件保存到用户指定位置；未指定时，使用当前对话输出目录，若没有明确输出目录则使用 `~/Downloads/codex-media/` 下本次独立目录。不得把临时结果写进工作台 `style-library` 或其他业务资料库。
- 不覆盖已有文件。下载先写入同目录临时文件，确认请求成功、文件非空且内容类型合理后再重命名；失败的部分文件不得作为成品交付。自行生成安全文件名，不直接把远端标题或响应文件名拼成路径。

## 调用契约

使用本机地址，不经公网域名。请求体由 JSON 序列化生成；不要把分享文案或用户输入直接拼入 shell 命令。可用 HTTP 客户端直接请求，或将 JSON 写入本次临时文件后使用 `curl --data-binary @文件`。

### 下载视频、音频或封面

`POST /api/tools/single-video/download`

请求头：`Content-Type: application/json`

```json
{"url":"完整视频链接","kind":"video"}
```

`kind` 可为 `video`、`audio`、`cover`，分别对应视频、音频和封面。成功响应是文件流，文件类型见 `Content-Type`，文件名提示见 `Content-Disposition`。失败通常返回非 2xx 状态及 `{"error":"原因"}`，不能把错误 JSON 保存成视频。

客户端下载时采用流式写入，不把大视频一次性读入内存；检查传输是否完整，必要时用本机 `ffprobe` 验证媒体文件。只请求下载时不额外调用转写接口。

### 转写视频文稿

`POST /api/tools/single-video/transcribe`

请求头：`Content-Type: application/json`

```json
{"url":"完整视频链接"}
```

可选 `titleHint` 为标题提示。成功响应结构：

```json
{
  "result": {
    "url": "原始链接",
    "platform": "bilibili",
    "text": "取得的文稿正文",
    "source": "platform_subtitle",
    "fallback": false
  }
}
```

`source` 可能为 `platform_subtitle`、`volcengine` 或 `metadata`。HTTP 200 不一定表示取得文稿：`source === "metadata"` 或 `text` 为空时，应按提取失败处理，展示 `fallbackReason`，不能把标题当文稿。

B站字幕按返回轨道的实际语言校验，不依赖标题；非中文或语言未标注的字幕不作为中文文稿。中文轨道不可用时继续识别原视频音频，成功返回 `source: "volcengine"`、`fallback: true`，并在 `fallbackReason` 中说明原因。

正文清洗前会检查可用性：清理后为空时报错；标题含汉字、正文无汉字且含至少 4 个拉丁文字词时，返回“转写结果语言待核实”，不保存为成功文稿。这个检查只用于发现明显的语言不匹配，不能判定原视频一定有中文口播，也不是歌词或音乐检测；正常中英混排与短产品名不按字数比例拦截。请核对原视频，只有配乐或画面文字的视频不能靠音频识别得到中文口播稿。

若返回非空正文但 `fallback` 为真，应说明降级原因；例如识别成功但模型清洗失败，只能标明“已取得转写，清洗降级”，不能宣称全部成功。保留已取得的正文，不编造或另用通用文案补齐。清洗结果不是保证逐字无修改的原始字幕。

正文可在对话中返回，长稿另存 UTF-8 `.txt` 或 `.md` 文件并给出绝对路径链接。若用户只要求转写，不另外保存一份视频，也不额外润色或改写正文。

## 执行与错误处理

1. 识别用户要求及链接，确定本次输出位置，然后只调用所需接口。
2. 转写可能持续数分钟，HTTP 客户端使用足够的总超时（例如 15 分钟），期间通过进程状态等待并向用户更新。不要将一次请求每隔几十秒重新提交；本接口没有幂等任务 ID。
3. 用户取消时终止本次客户端请求；接口将请求取消信号传给处理链路，但已提交的第三方识别是否停止取决于该服务，不承诺退还调用额度。
4. 连接失败时说明本机工作台服务未连接；403 可能是当前运行模式仅开放毛利接口；404 说明运行版本可能没有该入口。不得为了调用而擅自启动、重启、切换或发布工作台。
5. 平台登录、限流、无媒体地址或识别配置错误，按接口实际错误给出处理建议，不改用账号采集来绕过。超时或断线可能已消耗识别额度，先说明结果未知，再决定是否重试。
6. 交付文件路径或文稿，并说明真实失败或降级项。仅在用户另行明确要求入库时，才进入相应业务流程。

不必每次调用 `/api/health`；该接口包含模型和外部服务探测。需要确认路由是否存在时，可对目标接口提交空 JSON：预期返回 HTTP 400 的参数错误，不会开始下载或转写。

## 实现定位

- 下载入口：`src/app/api/tools/single-video/download/route.ts` → `prepareLinkSourceDownload()`。
- 转写入口：`src/app/api/tools/single-video/transcribe/route.ts` → `transcribeLinkSource()`。
- 两个处理函数均位于 `src/lib/transcription.ts`。不要混用会写入账号转写记录的 `transcribeVideo()`。
- 已存在的后台 `single-video-transcribe` 任务会持久化任务结果，不用于本说明的临时对话调用。

维护接口时同步本说明。修改工作台代码仍须遵守仓库 `AGENTS.md`；仅调用接口无需扫描整个仓库。
