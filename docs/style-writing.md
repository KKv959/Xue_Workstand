# 账号风格链路

原稿 → 逐篇提炼讲法 → 汇总风格卡 → 风格卡与新素材直接成稿。

风格卡解释作者的口吻、观察角度、句子节奏和衔接方式。它不是文章模板或禁用清单。写稿不重新选样，不生成计划，不追加自动字数、禁词或审核报告；用户的要求直接交给模型。

## 实现

- 学习：读取已转写原稿，去重后逐篇深入分析讲法，再汇总成卡。逐篇分析使用自然、多段的具体分析和可选的少量原句，不再要求用途、段落节拍、衔接规则、场景边界或限制清单。
- 资料库手动点击“重新总结”时，全部逐篇分析和最终风格卡都会重新生成；普通自动更新仅复用输入、提示词版本和模型配置均未变化的逐篇分析。
- 写稿：已有风格卡、独立保存的偏好、本次要求与素材一起输入，一次成稿。文档读取、视频转写及用户启用的联网检索仍按各自流程完成。
- 续改：使用已保存的风格和资料，不重新采集。旧稿已有的原文快照仍可使用；新稿不附带原文。
- 不自动覆盖已有卡片。重新归纳沿用原子写入、历史归档、并发编辑冲突检查和引用校验；旧格式分析缓存保留但不再使用。`writerContext.plan` 在新稿中为 `null`，历史结构仍能读取。

提示词集中在 `src/lib/writer-prompts.ts`；本地选取原文在 `src/lib/style-reference.ts`。模型与任务中心、存储、API 返回结构保持兼容。

## 稿件与资料契约

- 多选风格卡时每卡独立成稿，只保存自身风格引用；有界并发处理，各稿失败或取消不覆盖其他已完成稿件。
- 初稿、续改和手动编辑保存为不可变版本链，保留父稿及版本关系；续改沿用该稿风格快照和父稿资料，不重新转写、抓取支持文档或联网。
- `originalSourceInput` 保留输入框原貌供恢复；模型使用解析后的 `input` / `sourceDigest`，不把内部素材包装当作用户原始输入。
- 支持文档经 `src/lib/support-documents.ts` 读取，正文失败显式报错；联网能力和资料复用详见[写作联网检索](api/writer-research.md)。

现有回归入口：`tests/writer-context.test.ts`（独立风格、快照、续改复用及部分成功），`tests/writer-editing-safety.test.ts`（编辑与取消时保留稿件和原始输入），`tests/foundation.test.ts`（原始输入持久化、历史版本与支持文档失败）。存储校验与恢复见[存储模块](../src/lib/storage/README.md)。

## GitHub 参考

2026-10-27 查阅：

- [DSPy](https://github.com/stanfordnlp/dspy)：将模型任务拆成明确的输入输出，并用固定样本比较效果。这里采用“原稿提炼 → 直接生成”的组织方式，没有引入 Python 框架、向量检索或自动优化器。
- [Promptfoo](https://github.com/promptfoo/promptfoo)：固定素材进行回归对照。仓库已有该依赖，继续使用现有评测入口。
- [xhs-style-imitation](https://github.com/ninggui/xhs-style-imitation)：参考其从博主作品提炼风格的方向；未采用固定八维指纹和多阶段约束。
- [stylometric-transfer](https://github.com/ngpepin/stylometric-transfer)：其量化指纹、规则及重试层不符合此次简化目标，且采用非商用许可，未复制或接入其代码。

## 对照验证

使用临时 `STYLE_LIBRARY_DIR`，3 篇合成口播原稿、2 个相同写作任务，没有读取或改写真实账号资产。脚本为 `.code/evaluate-style-chain.mjs`，结果为 `.code/style-chain-baseline.json` 和 `.code/style-chain-distilled.json`。实际归纳与写稿模型均为 `gpt-5.6-sol`；归纳的订阅调用受额度/限流影响，按原配置使用备用节点。

| 同一组合成样本 | 旧链路 | 当前链路 |
| --- | --- | --- |
| 归纳模型调用 | 3 次逐篇分析 + 1 次归纳 | 逐篇分析 + 1 次归纳 |
| 归纳总耗时 | 124.9 秒 | 取决于样本数量和并发 |
| 风格卡字符数 | 4708 | 按作者特点自然组织 |
| 每篇正文模型调用 | 1 次 | 1 次 |

旧对照保留作历史记录，不代表当前链路。当前链路恢复逐篇深度分析，但只保留自然分析和可选原句，不再扩成结构化研究报告；最终汇总沿用老版深度风格卡的思路。

代码验证覆盖风格、保存与续改链路；类型检查和相关 lint 通过。浏览器在临时资料库实际生成并保存 V1，确认每稿只有自身风格引用、`plan: null`、无原文选样。模型设置页分别配置逐篇分析和风格卡汇总。

本次轻量格式变更通过 24 项风格链路测试、相关 lint 与 TypeScript 检查；真实风格卡不会在代码更新时自动重建。
